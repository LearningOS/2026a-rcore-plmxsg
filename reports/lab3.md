# Lab 3：进程管理与 Stride 调度

## 实现总结

`spawn` 直接加载目标程序，建立父子关系并将子进程加入就绪队列。`set_priority` 接受不小于 2 的优先级。调度器选择累计 stride 最小的就绪进程，并按优先级计算本次步长。计时和匿名映射适配了本章的进程结构，`fork` 复制匿名页，进程退出时回收这些页。

## Stride 问答

### 1. 8 位计数溢出会怎样？

P2 的 stride 从 250 加到 260，存入 8 位无符号整数后变成 4。普通整数比较会认为 4 小于 P1 的 255，于是再次选 P2。按实际累计值比较，P1 的 255 小于 P2 的 260，本应先选 P1。

### 2. 为什么最大与最小 stride 的差不超过 BigStride / 2？

在进程集合固定、初始 stride 相同且忽略溢出的条件下，每次只增加当前最小值。优先级至少为 2，所以一次增量至多为 BigStride / 2。如果增加后的值没有超过原最大值，最大值不变而最小值不会下降。如果它成为新最大值，它与新最小值之差也不超过这次增量。因此这个上界可以在每轮调度后保持。

### 3. 如何让 BinaryHeap 优先弹出真实 stride 最小的进程？

当真实 stride 的差值小于计数范围的一半时，环绕减法的结果解释为有符号数后，可以用其正负判断先后。Rust 的 `BinaryHeap` 默认弹出最大元素，因此比较时还要反转顺序。下面是题目要求的 `partial_cmp`，实现 `Ord::cmp` 时也应采用相同顺序。

```rust
fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
    let delta = self.0.wrapping_sub(other.0) as i64;
    Some(delta.cmp(&0).reverse())
}
```

本实验的调度器实际使用 `u128` 累计 stride，并线性扫描就绪队列选取最小值。上面的比较器用于回答固定宽度计数回绕的问题。
